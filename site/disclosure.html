Disclosure

How this was built, and how we report findings.

Two separate obligations: being honest about how this was built, and being careful about what we tell the world.

01 — AI assistance and human checkpoints

AI assistance was used

  • Scaffolding and boilerplate
  • Drafting documentation
  • Drafting the labeler’s rules table — deterministic, no model at runtime
  • Suggesting Cypher that a human then reviewed

Human checkpoints

  • Every query was run against a live FalkorDB instance before commit. The pinned 6.0.2 image is used in CI and in compose; one public-README run used 6.0.1 and is logged as such.
  • Every benchmark number was read by hand from eval/results/*.json; every transcript from docs/live-evidence/.
  • The gold label set was hand-labelled, with no model input.
  • The graph model and architecture decisions are ours.

Every query, index and parameter choice is in the repository. If a number cannot be traced to a file in the repo, treat it as a bug and tell us.

02 — what we learned

The short version, because it shaped the product more than any feature did.

We started with a router, and dropped it

Our first plan was a router that trims MCP tool schemas to save context. The pain is real, but the fix does not need a graph — keyword search, embeddings or built-in tool search all work, and Anthropic already ships one. A product that survives deleting its graph is a thin wrapper around a data store, so we replaced it with a problem that is a path.

The docs were ahead of the engine

The engine’s docs describe a shortest-path index absent from the pinned image, and a parameter-passing form that silently fails to bind. We verified by execution, wrote the fallbacks, and recorded both rather than quoting a benchmark we could not reproduce.

The cut is not the flow

Our first fix query expected algo.maxFlow to return a cut. It returns flows; the cut is ours to compute. That code is where the “cheapest permission” logic lives, and the product is better for it.

Accessibility is measurable

The two colours carrying the entire explanation — private data and the leak path — measured below the bar we had claimed. We replaced them; the palette check now measures every pair instead of trusting them.

Retrieval is not the product

A published paper already handles vector-seeded, graph-aware tool selection on a public benchmark. We cite it and do not re-implement it. The missing piece is the computed, verified fix; that is what we built.

03 — reporting findings in other people’s servers

Composition is not a vulnerability. Most of what we surface is a combination of servers that each behave correctly. We treat that distinction as a hard rule, not a courtesy.

We file an issue only when it is one server’s fault

Either a single server holds all three legs, or its annotations are wrong enough to make clients mislabel it. A pair of correct servers is not reported to either maintainer.

Private channel first, always

We read SECURITY.md before anything else. Where a private channel exists, we use it and wait for a reply before mentioning it publicly.

Capabilities, never payloads

Our reports describe what a tool can read or write, suggest annotation fixes and scopes, and never include a working injection or steps against real users.

Every finding is disputable

A maintainer can ask us to correct or remove a finding, with no argument. Open an issue, or use the private channel below.

Found a problem in LethalPath?

Please report it privately first, so we can ship a fix before it is public. We aim to acknowledge within 48 hours.
