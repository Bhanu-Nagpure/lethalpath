THE FIX — CALL algo.maxFlow ⇒ 9 grants

Breaks 567 of 567 paths · revokes 9 write grants (every github write plus git.push) · verified 0 remain when the same query re-runs without them. When cuts tie on cost the engine prefers the write side — the agent keeps its read and loses only the publish.

Why this edge?

example deny list · illustrative

- allow: git.push, github.* writes # 567 paths end in a public sink
+ deny: the nine write grants # re-run without them: 0 remain

The CLI prints a revoke list; it does not export a policy file. This block shows how that list maps onto a deny list.

The queries, verbatim

Cypher executed — leak-path query · read-only · 3 s timeout · LIMIT capped at 100 
MATCH inj = (u:Resource {trust:'untrusted'})-[:FLOWS]->(:Tool)-[:FLOWS]->(ctx:Context)
MATCH leak = (p:Resource {sensitivity:'private'})
              -[:FLOWS*1..5]->(ctx)
              -[:FLOWS*1..5]->(s:Resource {visibility:'public'})
RETURN u.kind AS injected_from,
       [n IN nodes(inj) | coalesce(n.kind, n.name, n.id)] AS injection,
       [n IN nodes(leak) | coalesce(n.kind, n.name, n.id)] AS chain,
       [n IN nodes(leak) WHERE n:Tool | n.name] AS tools,
       length(leak) AS hops
ORDER BY hops ASC LIMIT 25
Cypher executed — minimum cut · one algo.maxFlow call; both canonical cuts derived in code 
MATCH (p:Resource {sensitivity:'private'})
WHERE p.visibility IS NULL OR p.visibility <> 'public'
WITH collect(p) AS src
MATCH (s:Resource {visibility:'public'})
WHERE s.sensitivity IS NULL OR s.sensitivity <> 'private'
WITH src, collect(s) AS dst
CALL algo.maxFlow({
  sourceNodes: src,
  targetNodes: dst,
  relationshipTypes: ['FLOWS'],
  capacityProperty: 'capacity'
})
YIELD maxFlow, edges, edgeFlows
RETURN maxFlow, edges, edgeFlows

One call, one relationship type (all 6.0.2 accepts); it returns flows, not the cut, so the residual graph is walked in mincut.ts to produce the edge set above. The cut is chosen by grant count, then declared-task cost, then the write side.
