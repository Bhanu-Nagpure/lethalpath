The problem

Three permissions you would approve. One path you would not.

No tool misbehaves. The bug is in the arrangement: one agent, one context, and three abilities that add up to exfiltration.

Replayed against published incidents from GitHub MCP, Supabase, WhatsApp and Postmark. See the evidence.

How it works

From config to a verified cut.

Three deterministic steps. There is no model in the runtime; the graph decides, and the CLI prints the receipt.

01

Read the config

Point scan at an MCP config. LethalPath labels every tool by what it reads and writes, redacts secrets before anything reaches the graph, and names tools it cannot classify.

02

Find the path

One Cypher traversal anchors on the shared context and returns the routes from untrusted input to a public sink, with every tool on the path named.

03

Cut and verify

algo.maxFlow computes the flow. LethalPath walks the residual graph, compares both canonical cuts, then re-runs the traversal with the revoked grants excluded.

The fix

A scanner tells you the risk. LethalPath tells you what to switch off.

algo.maxFlow returns flows, not a cut. LethalPath walks the residual graph, compares both canonical cuts, and picks the one that costs fewer grants and keeps more declared tasks.

MATCH (p:Resource {sensitivity:'private'})
WHERE p.visibility IS NULL OR p.visibility <> 'public'
WITH collect(p) AS src
MATCH (s:Resource {visibility:'public'})
WHERE s.sensitivity IS NULL OR s.sensitivity <> 'private'
WITH src, collect(s) AS dst
CALL algo.maxFlow({
  sourceNodes: src,
  targetNodes: dst,
  relationshipTypes: ['FLOWS'],
  capacityProperty: 'capacity'
})
YIELD maxFlow, edges, edgeFlows
RETURN maxFlow, edges, edgeFlows

Built on FalkorDB

The graph is not a store. It is the product.

The leak is a reachability question: can an untrusted input reach a public sink through this agent’s context? A vector index can rank tools; it cannot answer that. The fix is a flow problem on the same graph.

  • Path query. One anchored traversal, bounded at five hops per segment, with the tools named on the path.
  • Fix query. CALL algo.maxFlow on one capacity relationship type, then a residual cut in code.
  • Read-only boundary. Every read uses GRAPH.RO_QUERY, with a 3 s timeout, a write-keyword guard and a LIMIT cap.
  • One graph per scan. scan_<name> isolates every config on one instance.

Limits

Know the edges.

  • Labels are inferred from tool names, not server code. Unmatched tools are named, never silently trusted.
  • Five hops per segment. The traversal is bounded around the context. Longer routes are outside the model.
  • The guard is a demo. Real MCP stdio, simulated tool results. No real GitHub, filesystem or git server sits behind it yet.
